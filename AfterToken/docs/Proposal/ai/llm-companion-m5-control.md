# 提案：AI 队友 M5 —— LLM 实时操控通道（"AI 开车"模式）

> 提案状态：已落地并在线实测通过（2026-09-08，DeepSeek deepseek-chat：一局 47 决策 100% 合法、平均延迟 ~855ms，combat→engage→loot 全链路实测）
> 提出时间：2026-09-08

> 关联模块：`docs/modules/ai/companion-system/`

## 1. 背景（说人话版）

现在队友的工作方式像**"自动驾驶 + 对讲机"**：

- 本地状态机（FSM）是自动驾驶——跟谁、走哪、打谁，全是它自己按规则算的；
- LLM 只是对讲机里的人——负责说话，最多喊一句"跟着我"（现在的 intent 只有 follow/hold/retreat 三个口令）。

用户做这个项目的目的之一是**验证当前 AI 在游戏里的实时操控能力**。所以要升级成"**AI 开车**"：每隔几秒让 LLM 看一眼战场，决定队友下一步干什么，队友就真的干什么。

**一个必须接受的现实**：LLM 每次回答要 1~5 秒，它永远做不了"压枪、走位"这种每秒几十次的操作。所以"AI 开车"的意思是——**AI 决定"去哪、干什么"，怎么走过去、怎么开枪还是本地程序管**。就像真人说"去那边架枪"，具体迈哪条腿不用管。

---

## 2. 目标

1. LLM 每隔几秒收到一份"战场快报"，从一张**固定的动作清单**里挑一个，队友就执行它。
2. 玩家在设置里可以开关这个模式（默认关，保持现在的自动驾驶）。关掉 = 现在的行为，方便做"AI 开 vs 程序开"的对比。
3. 每次 AI 做决策都记录下来（多久回话、选的动作合不合法、花了多少 token），出数据回答"现在的 AI 到底能不能实时操控游戏角色"。
4. 断网/断联时自动退回现在的自动驾驶，行为无损。

---

## 3. 详细设计

### 3.1 AI 能选的动作清单（技能表）

LLM 每次只能从这张表里选一个动作，防止它瞎编：

| 动作 | 意思 | 对应现有实现 |
|---|---|---|
| `follow` | 跟着玩家 | Follow 状态（已有） |
| `hold` | 原地驻守 | Hold 状态（已有） |
| `move_to` | 去某个位置（带坐标） | PingMove 状态（已有，坐标从参数来） |
| `engage` | 打某个敌人（带敌人编号） | Engage 状态（已有，目标从参数来） |
| `loot` | 去捡某个掉落物（带编号） | PingMove 到掉落物位置（已有能力） |
| `retreat` | 撤退收缩 | 映射驻守+远离威胁（已有） |
| `extract` | 去撤离点 | PingMove 到撤离点（已有能力） |
| `none` | 维持现状 | 不动 |

每个动作都对应一个已经实测过的 FSM 状态，**没有新行为要写**——M5 只是把"谁来选状态"从本地规则换成 LLM。

### 3.2 给 AI 看的"战场快报"（每次决策的输入）

每隔几秒（安全时 8 秒、打架时 3 秒，表上可配），给 LLM 发这样一段文字：

```
你在 (12.5, 3.2)，血量 180/200。玩家在 (14.0, 4.1)，血量 65/100。
附近有 2 个敌人：#301 在 (18, 6) 正在追玩家；#305 在 (8, 1) 在巡逻。
地上有 1 个掉落物：#77 在 (10, 2)。
撤离点在 (18, 18)。
当前你在执行：follow。
可选动作：follow / hold / move_to / engage / loot / retreat / extract / none
```

LLM 必须回一个 JSON（在现有契约上加 `action`/`target` 两个字段）：

```json
{
  "action": "engage",
  "target": "301",
  "say": " hostile on your right, engaging.",
  "mood": "tense"
}
```

`target` 填敌人编号/掉落物编号/坐标，按动作类型解释。回慢了（超过 3 秒）这条决策作废，队友继续干手上在干的事。

### 3.3 决策怎么进状态机（复用现有管道）

```
DecisionDriver（新，每 N 秒发快报收决策）
    │
    │  合法检查：动作在清单里？目标还活着？超时了吗？
    ▼
Context.PendingRequest（M1 就预留好的入口，带目标参数）
    │
    ▼
现有 FSM 执行（寻路/开火/跟随全是旧代码）
```

硬规矩（本地代码，LLM 无权改）：队友死了 / 血量低于 30% 撤退 / 玩家按了标点——这三件事永远优先，LLM 的决策顶不掉。

### 3.4 开关与回退

- 设置项（M4 设置面板里加，配置文件里先加 `controlMode: "llm" | "fsm"`，默认 `fsm`）。
- `fsm` = 现在的行为；`llm` = AI 开车。
- LLM 断联（Offline 状态）时自动落回 `fsm`，恢复后自动切回。这个开关本身就是现成的 A/B 对照实验。

### 3.5 遥测（验证目标的产出物）

每次 LLM 决策记一行，存 `Logs/companion_control.csv`：

| 字段 | 说明 |
|---|---|
| 时间戳 | |
| 战况 | safe / combat |
| 决策耗时 | 从发出到收到（毫秒） |
| 是否合法 | 动作在清单内 + 目标有效 + 未超时 |
| 选的动作 | engage 等 |
| token 用量 | 这次请求花了多少 |

GM 命令 `companion stats` 现场看汇总（平均延迟、合法率、token/局）。换不同模型（改 endpoint）跑同一关，就是现成的横向对比。

### 3.6 文件改动清单

| 文件 | 改动 |
|---|---|
| `AI/Llm/DecisionDriver.cs`（新建） | 决策节拍器：采快照 → 发请求 → 校验 → 写 PendingRequest；遥测记录 |
| `AI/Llm/PromptBuilder.cs` | 加"战场快报"组装 + 动作清单说明；契约加 action/target |
| `AI/Llm/CompanionBrain.cs` | 接入 DecisionDriver（llm 模式时才 Tick 它）；断联自动回退 |
| `FSM/Companion/CompanionStateBase.cs` | PendingRequest 执行时把 userData（目标坐标/编号）交给状态（PingMove/Engage 已支持目标参数，补读取） |
| `Configs/GameConfig/Datas/companion.xlsx` | 加字段：安全/战斗决策间隔、决策超时、controlMode 默认值 |
| `GM/GMController.cs` | `companion stats` 命令 |
| `Logs/companion_control.csv` | 遥测输出（不入库） |

聊天频道（safe_idle 闲聊）和操控频道**分开计时分开算钱**，互不挤占。

## 4. 风险与决策

| 风险 | 处置 |
|---|---|
| LLM 回话慢（打架时 3 秒一拍可能嫌慢） | 决策间隔表上可配；选快模型（kimi-k2-turbo / DeepSeek / 4o-mini 这类）；回慢了队友只是"多干 3 秒手上活"，不会死 |
| LLM 瞎编动作/目标 | 白名单 + 目标有效性检查，非法直接丢弃记遥测（这正是要测的数据） |
| 决策太频繁烧钱 | 节拍 + 单局限额已有；操控频道单独限额（表上可配） |
| AI 决策看起来"犯蠢" | 正常——这正是验证目标要暴露的。遥测 + 回放（csv 里存了快照）可以复盘每个决策 |
| 玩家标点和 AI 决策打架 | 玩家标点永远赢（硬规矩），AI 下一拍会看到"当前在执行 ping_move" |

## 5. 实施步骤

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M5a 技能表接线** | 动作清单 8 项全接到 FSM；PendingRequest 带目标参数 | 反射发决策指令，队友真实执行全部 8 个动作 |
| **M5b 决策节拍器** | DecisionDriver + 快报 prompt + 契约扩展 + 开关/断联回退 | llm 模式下队友全程由 AI 指挥打完一局 101 |
| **M5c 遥测** | csv 记录 + GM stats | 出一局完整数据；换模型出对比 |

M5a 不需要 API key（本地反射模拟 LLM 决策即可测）；M5b/c 需要真实 key。

---

## 6. 结论

不动任何玩法行为代码，只在"谁来选状态"这个点上加一个 LLM 驾驶位。本地 FSM 既是执行器也是安全网。这个形态就是当前业界验证"AI 实时操控游戏角色"的标准做法（Voyager / Generative Agents 同款分层），且天然带 A/B 对照和量化数据产出，正好服务项目的验证目标。
