# AfterToken 项目架构方案（3D 时代）

> 本文档描述 AfterToken 的**当前**架构（2026-08-31 重写），取代 2D 时代的旧规划稿。
> 细节入口：项目上下文 `docs/CONTEXT.md`；分篇深入 `docs/framework/01~08`；模块实现 `docs/modules/`。

---

## 一、项目定位

3D 俯视角**搜打撤**射击 + 模拟经营双玩法原型：

```
主菜单 → 基地（模拟经营：建筑/生产/订单/NPC 任务）
           │ Deploy 选关（LobbyUI / 选关传送门）
           ▼
        战斗关卡（3D 俯视射击：杀怪/开箱/捡纸条/做任务）
           │ 撤离点倒计时 或 死亡
           ▼
        回基地（战利品入仓库 → 货币/经验/解锁 → 经营消耗）
```

- 基地即据点，一局结束（撤离/死亡）都回到基地，形成搜打撤闭环。
- 玩家/敌人为 3D 胶囊，武器为挂在角色右侧的长方体占位模型；渲染管线为 **Built-in**。

## 二、技术栈与管线

| 层 | 选型 | 说明 |
|----|------|------|
| 引擎 | Unity 6000.0.76f1 | Built-in 渲染管线，3D 物理 |
| 框架 | TEngine | Procedure/UI/Scene/Resource/Timer/Pool 等模块 |
| 热更 | HybridCLR | GameLogic/GameProto 全热更 |
| 资源 | YooAsset | 编辑器下 EditorSimulateMode，按 location 加载 |
| 配置 | Luban | `Configs/GameConfig/Datas/*.xlsx`（部分表 CSV 数据源）→ `gen_code_bin_to_project.bat` 导表 |
| 异步 | UniTask | 全流程异步/加载 |

## 三、程序集划分

| 程序集 | 路径 | 热更 | 职责 |
|--------|------|------|------|
| `Assembly-CSharp` | `Assets/Launcher/` 等 | ❌ | 启动器、主包流程（Launch→…→LoadAssembly→StartGame） |
| `TEngine.Runtime` | `Assets/TEngine/Runtime/` | ❌ | 框架核心 |
| `GameProto` | `Assets/GameScripts/HotFix/GameProto/` | ✅ | Luban 生成代码、协议/数据结构 |
| `GameLogic` | `Assets/GameScripts/HotFix/GameLogic/` | ✅ | 全部玩法业务逻辑 |

**依赖规则**：`GameLogic → GameProto → TEngine.Runtime`，禁止反向依赖。

## 四、GameLogic 目录结构（现状）

```
GameLogic/
├── GameApp.cs              # 热更入口：接管流程状态机（ADR-0004）
├── GameModule.cs           # 业务模块统一访问入口
├── Procedure/              # 流程：MainMenu / Simulation / Battle + GameplayProcedureBase
│   ├── BattleContext.cs        # 跨流程关卡上下文（静态，临时方案）
│   ├── PlayerAttrStore.cs      # 玩家属性跨场景暂存（变动即存）
│   └── PlayerStateContext.cs   # PortalPlayerState：传送门场景上下文
├── System/                 # 场景运行时系统（挂 BattleRoot/SimulationRoot）
├── Simulation/             # 经营玩法：建筑/生产/订单/时间/相机/输入/玩家控制器
├── Narrative/              # 叙事：QuestSystem、DialogueFlagSystem、条件/动作表达式
├── Shared/                 # 跨玩法共享：存档/货币/背包/档案/解锁/联动
├── Entity/                 # 场景实体：Player/Enemy/Npc/Portal/Projectile/Extraction/LootContainer/Note/Pickup
├── FSM/                    # 玩家/敌人状态机
├── Weapon/                 # 武器抽象（IWeaponOwner 等）
├── Item/                   # RunInventory（战局背包）/Warehouse（仓库）
├── IEvent/                 # 事件接口（19 个，见下）
├── Config/                 # Luban 表的运行时封装（*ConfigMgr）
├── UI/                     # UIWindow（全部 Prefab 驱动；经营类在 UI/Simulation/）
├── Module/UIModule/        # TEngine UI 的本地扩展（UIWindow 基类等）
├── Pool/                   # 对象池
├── Navigation/             # 导航
├── GM/                     # GM 调试命令
└── SingletonSystem/        # 常驻对象管理（Retain/Release）
```

## 五、流程架构

热更域流程（`GameApp.StartGameLogic()` 注册）：

| 流程 | 场景 | 常驻 UI |
|------|------|---------|
| `ProcedureMainMenu` | `MainMenuScene` | `MainMenuUI` |
| `ProcedureSimulation` | `SimulationScene`（基地） | `SimulationMainUI`、`QuestTrackerUI` |
| `ProcedureBattle` | `BattleScene_3D_L01~L03`（`level.xlsx` 的 `sceneName`） | `BattleMainUI`、`QuestTrackerUI`、`DamageNumberUI`、`HitFeedbackUI`、`MinimapUI` |

- 大厅（Lobby）概念已废弃：选关是基地内的 UI 窗口/传送门，不是独立流程。
- 所有流程继承 `GameplayProcedureBase`：统一 LoadingUI 场景加载、CancellationToken、`OnLeave` 全量清理（CloseAll/RemoveAllTimer/UnloadUnusedAssets）。
- 切换走 `GameApp.ChangeProcedure<T>()`（反射调 TEngine 内部 FSM，已知技术债，见 ADR-0004）。
- `ProcedureStateRecorder` 用 PlayerPrefs 跨 Play 恢复流程（排查异常时先想到它）。

### BattleRoot / SimulationRoot 系统挂载

`ProcedureBattle.InitializeBattleSystems()` 在 BattleRoot 上挂：
Input / Player / Weapon / AimAssist / Ballistic / Projectile / Battle / EnemySpawn / Drop / HitFeedback / Pool / Navigation / Portal / LootContainer / Note / Minimap / Extraction / PlayerDeathHandler / GMController。

`ProcedureSimulation` 在 SimulationRoot 上挂：
SimulationSystem（其内部再挂 SimTimeSystem / BuildingSystem / ProductionSystem / OrderSystem / BuildingPlacementSystem）/ SimulationInputSystem / PortalSystem / NpcSystem / DialogueSystem（相机由 `SimulationCameraController` 挂主相机）。

跨场景常驻的逻辑做成**纯 C# 静态类**（不挂场景）：`QuestSystem`、`CurrencySystem`、`InventorySystem`、`PlayerProfileSystem`、`UnlockSystem`、`SaveSystem`、`DialogueFlagSystem`——订阅全局事件总线，场景销毁不影响。

## 六、核心机制

### 6.1 事件总线

所有跨系统通信走 TEngine 事件接口（`[EventInterface]`），`IEvent/` 下 19 个接口：

- 战斗：`IBattleInputEvent`、`IBattleEvent`、`IPlayerEvent`、`IEnemyEvent`、`IWeaponEvent`、`IProjectileEvent`、`IHitFeedbackEvent`、`ICameraEvent`
- 共享：`IItemEvent`、`IInventoryEvent`、`ICurrencyEvent`、`IPlayerProfileEvent`、`IUnlockEvent`
- 叙事/场景：`IDialogueEvent`、`IQuestEvent`、`INpcEvent`、`IPortalEvent`、`ISimulationEvent`

约定：发布 `GameEvent.Get<IxxxEvent>()?.OnXxx(...)`；订阅用 `GameEventMgr.AddEvent` 并在 `OnDestroy` 中 `Clear()`；UI 用 `AddUIEvent` 自动随窗口生命周期解绑。

### 6.2 配置驱动（Luban）

数值一律走表，改表后跑 `gen_code_bin_to_project.bat` 导表生效。主要表：

- 战斗：`weapon.xlsx`（5 武器全参数）、`level.xlsx`（101~103：敌人/奖励/撤离时间/默认武器）、`enemy.xlsx`、`ballistic.xlsx`、`battle.xlsx`、`buff.xlsx`、`pickup.xlsx`、`lootcontainer.xlsx`
- 相机：`camera3d.xlsx`（战斗/经营两场景**同源**：俯仰 60°、偏移 (0,5,-3.5)、FOV 45、玩家锚定画面底部 1/4）
- 经营：`building.xlsx`、`production.xlsx`、`order.xlsx`、`sim_time_config.xlsx`
- 叙事：`npc.xlsx`、`dialogue.csv`/`dialoguenode.csv`、`quest.csv`/`questobjective.csv`、`note.csv`
- 共享：`item.xlsx`、`inventory.xlsx`、`unlock.xlsx`、`playerlevel.xlsx`、`portal.xlsx`

新表要同步 `__beans__.xlsx`/`__tables__.xlsx` 与两处 `ConfigSystem.cs` 的 `_tableFiles` 白名单（GameProto 与 CustomTemplate 必须一致）。

### 6.3 UI 架构

- TEngine `UIWindow` + `[Window(UILayer, location)]` 声明式注册；**全部 Prefab 驱动**（`Assets/AssetRaw/UI/`，经营类在 `Simulation/` 子目录）。
- 渲染：ScreenSpace-Camera，统一走远端 `UICamera`（方案 D，见 `docs/Proposal/ui/ui-render-architecture.md`）。
- 节点命名前缀约定（`m_text_`/`m_btn_`/`m_rect_`/`m_img_`/`m_slider_`），`ScriptGenerator()` 按路径绑定。
- 新建 UI Prefab 根节点必须挂 `Canvas` + `GraphicRaycaster`；`OnCreate` 调 `FixFullScreenCanvas()` 拉伸全屏。
- 游戏内 UI 文本一律英文（现阶段规定）。
- 光标/准星配对：菜单类 UI 开 → `CursorManager.ShowCursor` + 隐藏准星；关 → 恢复。HUD 类（QuestTrackerUI 等）不碰光标、不挡射线。

### 6.4 存档

`SaveSystem`（`Shared/SaveSystem.cs`）集中管理 `SaveData`：任务段（quest）、对话标志段（dialogue）、档案/解锁/货币等。原则：**变动即存**，不依赖退出时统一落盘；新增字段靠默认值兼容旧档，不做版本迁移。玩家战斗属性另有 `PlayerAttrStore`（变动即存，进基地清空）。

### 6.5 搜打撤数据流

- `RunInventory`（战局临时背包）↔ `Warehouse`（仓库）：撤离时 `PortalSystem.ExtractToBase` 整批转仓库；死亡全丢。
- `CrossPlayLink.OnBattleExtracted(levelId)`：撤离结算挂钩——发金币/经验（`TbLevel.rewardGold/rewardExp`）、记通关驱动 `UnlockSystem` 关卡链解锁、推进任务 extract 目标。
- `BattleContext.CurrentLevelId`：选关窗 → 战斗流程的关卡上下文（临时静态方案）。

### 6.6 叙事三层

内容表（Luban）→ 解释器（`DialogueSystem` / `QuestSystem`）→ 呈现（`DialogueUI` / `QuestLogUI` / `QuestTrackerUI` / NPC 头顶标记）。
共用最小领域语言：条件 `flag:/quest:/level:`，动作 `flag:/give:/quest:accept/turnin`（`NarrativeCondition`/`NarrativeAction`）。
NPC 有任务时对话出任务枢纽选项（Turn in/Accept/Just chatting），选项由节点表条件动态生成，接取走确认窗。

## 七、表现层策略

- 原型期美术一律占位：胶囊角色、长方体武器、纯色/网格地面、primitive 建筑。
- 特效优先 shader 化（不引粒子资源）：爆炸 = `ExplosionFireball` + `ExplosionShockwave`（Built-in ShaderLab，`ExplosionEffectDriver` 自驱动自毁）；小地图 = 正交俯视一次性烘焙成静态纹理（Unlit/Color 平色），不做实时 3D 渲染。
- 打包提醒：运行时加载的 shader 需加 Always Included Shaders。

## 八、已知技术债

1. **GameApp 反射切换流程**：长期应推动 TEngine 暴露公开 `ChangeState<T>()`。
2. **BattleContext 静态状态**：跨流程数据应迁移到正式运行时数据层。
3. **双 UIRoot 嫌疑**：运行时存在两个 UIRoot/两个 EventSystem 的告警，待排查。
4. **EditorSimulateMode**：真机包需配置 YooAsset 真实构建 + HybridCLR AOT 元数据验证。
5. **交互仲裁器缺失**：Portal/Note/NPC/容器触发区重叠时无统一仲裁（P0 待做）。
